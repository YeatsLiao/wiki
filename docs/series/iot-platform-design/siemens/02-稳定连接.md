# 西门子 · 稳定连接：工业协议与边缘网关

> 技术栈：MindConnect Nano / IoT2040 / Lib / Software Agent + S7 / Modbus / OPC UA 协议终结
> 适用场景：老设备不联网、协议不统一、车间断网时，如何稳定接入

连接是工业 IoT 的第一公里。消费 IoT 可以设备直连云，工业里这几乎不成立：老设备不联网、协议不统一、车间还可能断网。在 MindSphere 里，这层叫 MindConnect——既是协议翻译官，又是断网时的缓冲垫。

在工厂网络里，"能 ping 通云"和"能稳定上送数据"是两回事。DMZ 默认不允许控制器出网，边缘网关在本地做协议终结、数据聚合、断网续传，把"不确定性"挡在车间内。

## 1.问题背景：协议碎片化与边缘接入之痛

- **协议碎片化且根深蒂固**：Modbus RTU 跑串口、OPC UA 走安全会话、S7 是西门子母语、Profinet 跑工业以太网。给老设备装新协议栈既不经济也不可行。
- **网络并不总在线**：车间到云专线会抖动，直连云让断连时数据直接丢失。
- **存量设备无网口**：大量 S7-300 连以太网都没有，必须靠网关间接取数。
- **安全分区（DMZ）**：IEC 62443 要求分区隔离，控制器不能直接暴露给 IT。

这些现实决定了：协议转换、续传、计算、同步放在边缘 MindConnect 上，比甩给云端更合理。

## 2.设计理念：边缘终结 + 只读不写 + 四种形态

### 2.1 边缘终结 vs 直连云

| 原因 | 直连云的后果 | MindConnect 的应对 |
|------|-----------|------------------|
| 证书与防火墙 | S7 不具备 TLS 能力 | 证书与隧道终结在网关 |
| 带宽与成本 | 1kHz 振动全量上云浪费带宽 | 边缘聚合 RMS，带宽降一个数量级 |
| 语义缺失 | 裸地址 "DB4.DBW10=235" 无人能懂 | Aspect 映射为"主轴轴承温度=52.3℃" |
| 时间基准 | 多设备各自计时无法对齐 | NTP/PTP 统一对时 |

### 2.2 四种接入形态

| 形态 | 适用场景 | 代价 |
|------|---------|------|
| Nano | 棕地产线，高可靠性要求 | 单价高于软件方案 |
| IoT2040 | 数据量小、试点场景 | 缓冲容量有限 |
| Lib | OEM 出厂即带云连接 | 需设备侧二次开发 |
| Software Agent | 已有 SCADA/历史库 | 依赖主机稳定性 |

### 2.3 只读不写与聚合收益

核心原则：**南向协议只读不写**，把云端误操作风险降到最低。

| 指标 | 全量直连 | 边缘聚合后 |
|------|---------|----------|
| 上送点数 | 1kHz 振动 = 1000/s | 10s RMS = 0.1/s |
| 防火墙 | 多端口、多方向 | 单一 443 端口 TLS 隧道 |

## 3.实际应用：灌装线 MindConnect Nano

食品厂 12 台灌装机，每台机柜装一台 Nano，S7 读 PLC、Modbus TCP 读称重仪表：

```yaml
mindconnect:
  agent: mindconnect-nano
  transport_period: 10
  protocols:
    - type: S7
      endpoint: tcp://plc-filler:102
    - type: modbus-tcp
      endpoint: tcp://scale-meter:502
  mappings:
    - source: "DB5.DBW2"
      variable: "pressure"
      unit: "bar"
    - source: "holding_register:40001"
      variable: "weight_deviation"
      unit: "g"
  upstream:
    endpoint: "https://gateway.<tenant>.mindsphere.io"
    buffer_on_disconnect: true
```

每周计划内断网期间，Nano 把快照写入本地缓冲，恢复后按时间戳补传。Aspect 映射集中管理——12 台机共用一份变量字典，保证"灌装压力"同名同单位。

选型决策链：有网口+长期可靠 → Nano；预算紧+试点 → IoT2040；OEM 新产品 → Lib；已有 SCADA → Software Agent。

## 4.注意事项

- **网关本身是单点**：关键产线建议同柜双 Nano 热备，Fleet Manager 监控心跳。
- **协议转换不是万能钥匙**：毫秒级安全回路必须留在 OT 内闭环。安全相关位（急停、联锁）一律不映射上云。
- **时间同步精度要匹配场景**：亚毫秒联动用 PTP，秒级监控用 NTP。在 Asset 元数据中记录时间来源。

## 5.小结

MindConnect 的本质是把"工业协议的混乱"挡在边缘，让云端只面对一种标准语言。四种接入形态覆盖绿地到棕地的全部场景，只读不写 + 边缘聚合是工业连接不可逾越的安全底线。
