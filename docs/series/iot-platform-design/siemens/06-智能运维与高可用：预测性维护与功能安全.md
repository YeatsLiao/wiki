# 西门子 · 智能运维与高可用：预测性维护与功能安全

> 技术栈：Predictive Learning + Anomaly Detection + Visualizer + Notebooks + 安全合规
> 适用场景：工业 IoT 的可观测、预测性维护、功能安全与系列收尾

前五篇把"连得上、存得下、看得懂、管得住"讲完了。最后一篇收口在两个最硬的要求上：预测性维护（把数据变成可执行的维护建议），以及功能安全与合规（工业 IoT 不可逾越的红线）。

## 1.问题背景：从"坏了再修"到"提前知道"

- **非计划停机代价极高**：一条产线意外停机，每分钟损失可能上万。事后维修是被动救火。
- **故障模式多样**：轴承磨损是渐进的，焊枪撞针是突发的，冷却液泄漏是缓慢的。不同模式需要不同检测策略。
- **安全不可妥协**：预测再准，也不能替代功能安全（SIL 等级、安全 PLC、急停回路）。

## 2.设计理念：可信数据之上的智能

### 2.1 智能分层

| 层级 | 能力 | 工具 |
|------|------|------|
| 可视化 | 实时看板、历史趋势 | Visualizer |
| 规则告警 | 阈值 + 持续时间 | Event Management |
| 异常检测 | 无监督学习挑出异常模式 | Anomaly Detection |
| 预测性维护 | 剩余寿命（RUL）预测 | Predictive Learning |
| 自定义分析 | 数据科学家自由建模 | Notebooks（Python/R） |

### 2.2 安全合规底线

- **功能安全**：安全相关闭环永远留在 OT 侧（SIS / 安全 PLC），云只做监控与预测
- **IEC 62443**：分区隔离、访问控制、审计日志
- **数据驻留**：跨国集团数据存指定区域，满足 GDPR

## 3.实际应用：从振动到维护建议

风机主轴振动经 Time Series 积累三个月数据后，Analytics 跑两条流：

1. Anomaly Detection 无监督打分，挑出振动模式偏离正常基线 30% 的设备
2. Predictive Learning 对历史退化曲线做回归，估算剩余可用天数

Visualizer 看板展示"本周预测需维护设备"列表，维护团队据此排计划。

## 4.注意事项

- **预测不是替代安全**：任何 AI 预测都不能替代功能安全回路。急停、安全 PLC、SIL 认证永远不可被模型绕开。
- **数据质量决定模型上限**：采样频率不统一、单位混用、时间戳错乱，再深的模型也是 garbage in garbage out。先治理数据管道，再谈智能。
- **模型要可解释**：给运维团队的不是"这台设备得分 0.87"，而是"主轴振动 RMS 在过去 7 天上升了 40%，建议检查轴承"。

## 5.小结

本系列六篇从头到尾讲了一条完整的工业 IoT 链路：**边缘连接 → 时序接入 → 资产建模 → 批量管理 → 智能运维**。

MindSphere 不是通用 IoT 的工业版，而是在 OT 的现实（老、慢、稳、险）与 IT 的诉求（新、快、活、智）之间，用专门的分层架构架起的一座桥。理解这套架构，才能真正理解工业 IoT 的设计取舍。
