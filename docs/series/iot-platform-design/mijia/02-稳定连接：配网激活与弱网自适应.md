# 小米米家 · 稳定连接：配网激活与弱网自适应

> 技术栈：米家 App 配网（扫码 / 蓝牙辅助）+ 一机一密 + 局域网 / 云端双通道（以小米米家 / MiOT 为案例）
> 适用场景：无屏设备如何自助配网、弱网如何保活

工业设备由工程师烧录配置、插上网线就能跑。米家设备却要让一个不懂 DNS 的用户，把 Wi-Fi 密码交给一个没有屏幕的灯泡。

配网之所以难，是因为它发生在「设备还没有身份、没有密钥、没有网络」的真空状态。米家要在这个状态下，把 SSID 与密码安全送进去，给设备建立「一机一密」的长期身份——还不能让用户学任何网络知识。

这一篇按「进得来（配网）→ 控得稳（双通道）→ 待得住（保活）→ 活得久（低功耗）」的顺序拆开看。配网是生死线——设备连不进来，后面的一切免谈。

## 1.问题背景：米家配网难与弱网下的真实痛点

### 1.1 设备没有输入界面

米家灯泡、插座连一个按键都吝啬，更别说屏幕键盘。用户怎么把「家里 Wi-Fi 叫什么、密码多少」塞进设备，本身就是难题；米家靠扫码配网、蓝牙辅助配网把这件事简化到「开 App 扫一下 / 靠近即可」。以米家智能驱蚊器这类极简设备为例，机身只有一个指示灯，所有信息交互都靠米家 App 与指示灯闪烁节拍完成，用户无需输入任何字符。

### 1.2 家庭 Wi-Fi 环境恶劣

2.4G/5G 双频混淆、信道拥挤、墙体遮挡、路由器不定期重启，连接天然脆弱。米家 Wi-Fi 设备大量使用 Wi-Fi+BLE 双模模组，正是为了多一条保底通道。

更棘手的是运营商定制路由器常开启「双频合一」，把 2.4G 与 5G 合并成同名 SSID。而多数低成本 IoT 设备只支持 2.4G，配网时极易连错频段失败。

### 1.3 用户容忍度极低

工业配网失败可以派工程师，米家配网失败用户只会给差评、退货。配网成功率直接决定小米云里的设备激活率。有数据显示，消费级 IoT 设备激活失败的高发段就在配网，往往不是设备坏，而是用户放弃了——一次失败就可能让整盒设备吃灰。

### 1.4 密钥不能明文飞

密码经手机发给设备，途中若被嗅探，等于把全家网络拱手让人。米家因此强调「一机一密」与证书链，密钥不下落明文。即便同处一个公共 Wi-Fi，凭证也要在加密通道内传输，且设备身份在云端可追溯，避免一台设备被冒名顶替。

### 1.5 电池设备要省电

门锁、门窗传感器靠电池供电，常年长连很快没电，必须能睡能醒。一枚纽扣电池要撑一年以上，设备绝大部分时间处于微安级深度休眠，仅在必要时短暂联网。若为「实时在线」保持长连，续航从一年缩到一周，产品直接不可用。

## 2.设计理念：为什么米家把配网、双通道、保活分开设计

配网、连接通道、保活其实是三件事，米家把它们拆开各自优化，因为各自的技术矛盾完全不同。

### 2.1 配网：一次性送身份与密钥

米家 App 根据设备能力选择扫码配网、蓝牙辅助配网（BLE 先把 Wi-Fi 凭证传给设备，再由设备去连路由器，最稳最友好）、或一键快连；目标是零输入或极简输入，且密钥不下落明文。扫码配网适合带二维码的设备（如摄像机），用户扫码即把配网信息编码进二维码，设备摄像头读取后直连。蓝牙辅助配网则对无摄设备最友好，BLE 建连的可靠性远高于在空口盲发 Wi-Fi 凭证。

### 2.2 一机一密：身份锚点

每台米家设备出厂烧录唯一密钥/证书链，云端按设备身份（did + Product ID + MAC）鉴权，而非按型号。这样一台被攻破不会连累一片，也是（六）设备安全的物理根基。设备连云时携带 token，云端校验通过才允许入网，token 与设备硬件绑定，无法复制到其他设备。

### 2.3 双通道：本地快、远程达

米家设备与米家 App 在同一局域网内走米家局域网协议，本地联动低延迟、断网仍可用；跨地域远程控制与多端同步走小米云（MiOT cloud，MQTT / HTTPS）。两条通道互补，既保体验又保可达。局域网协议基于本地发现（如 mDNS）与轻量请求响应（如 CoAP/HTTP 本地端口），App 与设备在同一网段内直连，不经过公网，延迟通常可压到百毫秒内。

### 2.4 保活与低功耗：不断且省电

长连 + 心跳（KeepAlive）探活，断线后指数退避重连，避免雪崩式重连打爆小米云。

心跳间隔按设备类型分级：常电设备几十秒到几分钟一次，电池设备尽量拉长甚至只在状态变化时上报。指数退避（1s→2s→4s…上限封顶）配合随机抖动，是防止海量设备同时重连的关键。

电池设备大部分时间深度休眠，靠 RTC 定时或 GPIO 中断（如开门）触发联网。BLE Mesh 低功耗节点由好友节点代收消息，自身只周期性短暂唤醒取信，把平均电流压到极低。

一句话：**配网解决「进得来」，双通道解决「控得稳」，保活解决「待得住」，低功耗解决「活得久」**。四件事各管一段，任何一段做不好都会单独成为用户痛点，所以米家把它们当作四条独立的产品线来打磨。

### 3.1 多模式配网并存

米家 App 根据设备能力选择扫码 / 蓝牙辅助 / 一键快连；带 BLE 的双模设备优先走蓝牙辅助，成功率最高、对路由器最友好，凭证经加密通道下发。以蓝牙辅助配网为例，流程是：设备进入配网态后广播 BLE 广播包 → 米家 App 发现设备并建立 BLE 连接 → App 把加密的 SSID/密码与账号 token 写入设备 → 设备断开 BLE 自行连接路由器 → 连云激活后向 App 回报成功。整个过程用户只需「靠近、点确认」，无需在设备端敲任何字符。

```text
// 米家 App 蓝牙辅助配网（代表性流程，非真实 SDK 源码）

1. 设备进入配网态，广播 BLE 广播包               // 设备端：Advertising

2. 米家 App 发现设备并建立 BLE 连接              // App 端：GATT Connect

3. App 写入加密的 SSID / 密码 + 账号 token        // 凭证经加密通道下发，明文不落地

4. 设备断开 BLE，自行连接路由器                  // 设备端：Wi-Fi STA 关联

5. 设备连云激活，向 App 回报成功                 // 云端：一机一密双向认证
```

### 3.2 一机一密激活

设备首次连云时，用出厂烧录的唯一证书链做双向认证，小米云为其建立长期身份与设备影子（见（四）），此后每次连接都按此身份鉴权。证书链由小米 PKI 签发，设备私钥存于安全存储区不可读出，云端验证证书有效性后，才把设备绑定到用户家庭。这一步同时完成「配网」与「激活」：配网解决连通，激活解决身份归属。

```json
// 米家设备「一机一密」身份锚点（代表性字段，主机名占位）

{

  "did": "1234567890",                    // 设备唯一 ID

  "product_id": "miot.light.v1",          // 产品型号

  "mac": "AA:BB:CC:DD:EE:FF",             // 网卡地址

  "token": "<bound-to-hardware>",         // 与硬件绑定的鉴权令牌，无法复制

  "pki": "https://api.miio.io/pki/root.crt" // 小米 PKI 根证书（占位）

}
```

### 3.3 局域网+云端双通道

同局域网内走米家局域网协议做本地操控与本地联动（断网可用）；远程与多端同步走小米云 MQTT/HTTPS，实现跨地域控制。用户在家中关灯，指令经局域网直连设备，延迟低且断外网也能用；人在公司想看家里摄像头，则走小米云隧道，由云端转发。两条通道在 App 侧自动择优：检测到同网段有设备就走本地，否则回退云端。

### 3.4 长连保活、低功耗与重连

连云后长连按心跳保活。网络抖动短暂失联时本地缓存关键状态，恢复后补报。断线后指数退避重连并加随机抖动保护云端——固件升级后海量设备同时重启，若都按同一节奏心跳会形成周期性流量尖峰。

路由器改密后设备重连失败，会重新进入配网态或走蓝牙辅助回连，避免永久失联。

电池设备进入深度休眠，仅在需要时建连上报：

- **门窗传感器**：事件触发上报，平时零通信，开门瞬间唤醒发送
- **温湿度传感器**：RTC 定时（如每 10 分钟）唤醒采样上报，兼顾时效与续航
- **BLE Mesh 低功耗节点**：关闭中继以省电，平均电流压到微安级

## 4.注意事项

- **配网失败要给用户「可救」的反馈**：只显示「配网失败」等于把用户逼到退货。应区分「设备没进配网态」「Wi-Fi 密码错」「路由器 5G 不支持」等具体原因，给出对应引导（如提示切 2.4G）。配网失败率应作为新品验收的核心指标。

- **一机一密要配套「丢失/转让」流程**：设备转卖、退货时，云端应吊销该设备 token 并清除家庭绑定。转让家庭时一并迁移场景与权限，而非只移设备，否则新主人会拿到一堆「失联设备」。

- **心跳与离线判定要权衡**：心跳太频繁费电、太稀疏难以及时感知掉线。一个常见坑是云端判定离线阈值比设备实际重连时间还短，导致频繁误报离线。本地联动是「体验底线」，远程控制是「增值能力」。

## 5.小结

米家消费级连接的第一性原理是「让人无感地把设备接进来，并让它在糟糕的家庭网络里又稳又省」：

- **配网**：多模式 + 一机一密 → 进得来且安全（一次性生死线）
- **双通道**：局域网 + 云端 → 控得稳（本地优先）
- **保活**：心跳 + 退避重连 → 待得住
- **低功耗**：深度休眠 + 事件唤醒 → 活得久

| 维度 | 工业/通用 IoT | 米家/MiOT 消费级 |
|------|-------------|---------------|
| 配网 | 工程师烧录、出厂预配 | 用户自助：扫码 / 蓝牙辅助 / 一键快连 |
| 身份 | 按型号 / 网关 | 一机一密、did+PID+MAC 双向认证 |
| 通道 | 单一稳定长连 | 局域网 + 云端双通道、本地优先 |
| 保活 | 专线冗余 | 心跳 + 指数退避重连、防雪崩 |
| 功耗 | 常电为主 | 电池设备深度休眠、事件触发唤醒 |
