# 第 2 篇：搭建仓颉开发环境

> 本系列第 2 篇。要写仓颉代码，先得把仓颉装到电脑上。这篇记录我在 Windows 上搭环境的过程和验证方法。

## 一、要装哪几个版本？

「共建计划」里的**纯仓颉**路线，要求成果**同时适配两个版本**：

| 版本 | 全称 | 用途 | 下载地址 |
|------|------|------|----------|
| **LTS 1.0.5** | 长期支持版（Long-Term Support） | 稳定，长期维护 | https://cangjie-lang.cn/download/1.0.5 |
| **STS 1.1.3** | 短期支持版（Short-Term Support） | 尝鲜，语法较新 | https://cangjie-lang.cn/download/1.1.3 |

> 💡 **新手建议**：别一上来就装两个把自己搞晕。**先装一个跑通流程**（我选了 STS 1.1.3，语法更新），等能编译、能跑测试了，再装另一个做双版本适配。两个版本同时存在需要做环境隔离/切换，那是后面的事。

我是 Windows 系统，所以下载 **Windows 版安装包**（选 x64 / x86_64 架构）。

## 二、安装步骤（Windows）

1. 到上面的地址下载对应版本的 Windows 安装包。
2. 双击安装程序，基本一路默认下一步即可。
3. 安装程序通常会**自动配置好环境变量**（把仓颉的 `bin` 目录加进系统 `PATH`）。如果没自动配，就需要手动把安装目录下的 `bin` 加到系统环境变量 `PATH` 里。
4. 留意安装完成界面的提示，有些版本会提示你用专门的终端或运行一个环境初始化脚本。

## 三、验证装成功了没有（最关键）

装完后，**一定要重新打开一个新的命令行窗口**（这样环境变量才会生效），然后运行两条命令：

```powershell
cjc --version
cjpm --version
```

这两个是仓颉最核心的两个命令行工具：

- **`cjc`** = Cangjie Compiler，**仓颉编译器**，负责把 `.cj` 源码编译成可执行程序。
- **`cjpm`** = Cangjie Project Manager，**仓颉包管理器**，类似 `npm` / `maven`，负责建工程、管依赖、跑测试、打包。后面开发全靠它。

## 四、我这边的真实输出

我运行后得到的结果是这样的（说明装成功了 ✅）：

```
C:\Users\yourname>cjc --version
Cangjie Compiler: 1.1.3 (cjnative)
Target: x86_64-w64-mingw32

C:\Users\yourname>cjpm --version
Cangjie Project Manager: 1.1.3
```

几个信息点解读：

- `1.1.3` —— 说明我装的是 **STS 版本**，符合活动要求的 STS 1.1.3。
- `cjnative` —— 仓颉的原生后端（编译成本地机器码，性能好）。
- `x86_64-w64-mingw32` —— 说明是 Windows 64 位环境（w64 + mingw32 是 Windows 下的工具链标识）。

只要 `cjc` 和 `cjpm` 两条命令都能正常打印版本号，环境就 OK 了。

## 五、常见坑（新手注意）

- **命令找不到（`不是内部或外部命令`）**：多半是 `PATH` 没配好，或者装完没重开终端。先关掉所有命令行窗口，重新开一个再试。
- **PowerShell 里用 `&&` 连接命令报错**：Windows 自带的老版 PowerShell 不支持 `&&`，要用分号 `;` 分隔，或者干脆一条条命令单独执行。
- **只装了一个版本**：没关系，先用一个版本把开发跑通，双版本适配是收尾阶段的事，不影响现在开始写代码。

## 六、这一步的收获

- 环境搭好了，`cjc` + `cjpm` 能用了，就具备了「写仓颉、编译仓颉、跑仓颉测试」的基础能力。
