# 求职面试手记：把面试当收费站，而不是终点

> 这是我毕业求职季与第一份工作前后留下的面试笔记，整理自当年的逐字稿和感想。有些认识现在看依然成立，有些则带着当时的稚气，一并保留，权当一份成长记录。文中涉及的公司、学校均已做匿名化处理。

## 一、面试观：三句话定基调

当年记下的三条核心，现在回头看依然是对的：

1. **想清楚自己适合什么工作**——这是所有准备的前提；
2. **评估自己的能力与目标岗位的匹配度**——匹配度决定通过率，也决定入职后的舒适度；
3. **不要把面试当成问答，而是一次开放、轻松的相互交流**——把得出结论的思考过程说出来，比背出结论重要得多。

还有一句我很喜欢的比喻：

> 面试不是终点，而是一个收费站。更多精力应该放在过了收费站之后要走的路上。

![职业心态便签](/images/essays/interview-note.png)

这张当年贴在桌上的便签写着：保持乐观、脚踏实地锻炼品质；想改变现状必须承担风险；不必非要卷，先改变思维方式。

## 二、接到面试通知后，先做功课

接到面试邀约不要只回一句"好的"，当时我的确认清单是：

- 确认面试时间；
- 公司核心业务/产品是什么；
- 岗位性质：是新增岗位还是替补岗位；
- 领导看过简历后的态度；
- 面试流程与面试官身份；
- 主动询问薪资待遇范围；
- 添加联系方式，保持沟通渠道。

面试前再 research 一下面试官的背景，面试中可以适当引导对方聊聊他负责的产品——不需要太深入，留一些探讨空间，也打开了后续持续沟通的可能性。

## 三、面试官在看什么

当时整理的"对人才的理解"框架，用物理量做类比：

| 维度 | 含义 |
| --- | --- |
| 速度 | 你做过的事情、你现在拥有的技能 |
| 加速度 | 未来的可能性：潜力与意愿 |
| 速度的方向 | 与行业及业务的匹配度 |

面试表现则拆成四个维度：

- **Communication**：输出表达能力、反应速度；
- **Problem solving**：根据问题给出有逻辑、经得住挑战的解法；
- **Execution**：hands-on 的落地能力、细节、同理心、timing；
- **思辨力/举一反三**：面试官说"由于某某原因，你这个方案不能执行，怎么办？"——考的就是换位思考。

以及一条朴素的提醒：过于装、伪装的人不会受到喜欢，要真诚。

## 四、逐字稿：我最受益的准备方法

把能想到的、经历过的面试问题全部**写成逐字稿**保存下来，是我那段时间做得最对的事。下面是几段当年的逐字稿（已脱敏），供参考它的颗粒度：

**自我介绍**（模板：时间线 + 职责 + 量化结果 + 技术栈收尾）：

> 我从 2022 年 12 月开始软件开发工作，在一家软件研发中心负责实验实训系统的原型设计、数据库设计、前后端开发与部署，实现了 15 个以上的功能模块；同时作为项目组长，负责团队的工作分配和进度管理，定期组织会议并向上汇报。目前技术栈以 Java 为主。

**优缺点**（优点给证据，缺点给改进动作）：

> 优点：喜欢逛技术博客和开源社区，乐于写文章分享技术，注重编码风格和代码质量。
> 缺点：对一些新兴框架不够熟悉，需要花更多时间学习；以前喜欢在休息日熬夜，现在有意识地强迫自己早点休息。

**项目难点**（讲决策，不讲苦劳）：

> 做 C 语言线上仿真实验环境时有两种方案：一是用 Linux 自带的 gcc 直接运行代码、靠输入输出重定向拿结果——实现简单，但如果用户提交了操作系统级的恶意代码，会直接威胁服务器安全；二是接入开源 OJ 沙箱。由于项目要服务约两万名师生，对并发和数据安全要求高，最终选择 Judge0 沙箱。这件事让我明白：技术方案一定要基于业务场景来选，能解决当前业务场景的方案就是好方案。

**离职原因**（真实 + 无怨气）：

> 上家公司可以转正，但我刚毕业，想去大城市发展。我和领导聊过，领导也支持我出去闯一闯。

## 五、反问环节的清单

轮到"你还有什么想问的"时，我准备的清单：

1. 当前岗位的明确工作内容；
2. 公司对该岗位的具体要求;
3. 是否有新人培训；
4. 团队人数与成员在公司的工作年限——如果很多人待得久，侧面说明公司还不赖；
5. 项目用到的技术栈；
6. 对某些具体框架（如 Spring Cloud）是否有要求。

## 六、一次关于"刷 KPI 面试"的思辨练习

当时在职场社区看到很多人抱怨"面试只是 HR 刷 KPI"，评论区一片情绪输出。我记下了一段很清醒的反驳，核心是五个反问：

1. 你到底遇到过多少次"岗位不招人只为凑 KPI"？总结过这类 HR 和 JD 的共同特点吗？
2. 你的简历是不是海投？是不是一份简历不改求职意向就投遍了不同行业的不同岗位？
3. 如果你判定下一个面试邀请是刷 KPI，理由是什么？你还会去吗？
4. 成年人要对自己的选择负责——去了才发现被拉去刷 KPI，是不是自己判断和选择的问题？
5. 面试前你做过行业分析和面试官背调吗？和 HR 通过几次电话？这家公司去年盈利吗？产品是什么、怎么做、卖给谁？

## 七、关于绩效公正性的一段引文

摘自谦谦的博客（[xqq.im](https://xqq.im/)），关于业务导向公司里技术向员工的处境：

> "有两个员工，一个负责写大量相对简单的业务，有持续的输出；另一个员工，独立开发核心库，难度高、工程量大、开发周期长，最后因外部原因 block 导致不能按时上线。最后第一个员工获得了较高的绩效评级，第二个员工获得了极低的分数，这公正么？"

选公司时，这个问题值得提前想清楚：这家公司如何评价"看不见短期产出"的工作？

## 八、几条零散但值得留的话

- 把问题放到合适的框架里，根据框架建立假设，用实验或数据分析来验证假设——这是用科学方法分析问题的能力，面试考的也是这个。
- 想做的、在做的、擅长做的，可能不是同一件事。
- 抽象与逻辑：透过表象看本质，从感性认识到理性认识，从定性关系到定量关系。
- 既有输入，也有输出；先有输入，后有输出；强调输入，自有输出。
